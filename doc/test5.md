````markdown
## 3. GitHub란 무엇인가

### 3.1 Git의 의미

Git은 파일의 변경 이력을 관리하는 프로그램입니다.

예를 들어 보고서, 프로그램 코드, 강의자료를 수정할 때 다음과 같은 내용을 기록할 수 있습니다.

- 누가 수정했는가
- 언제 수정했는가
- 어떤 내용을 수정했는가
- 이전 버전과 무엇이 달라졌는가

Git은 이러한 변경 기록을 체계적으로 관리하는 **버전 관리 도구**입니다.

---

### 3.2 GitHub의 의미

GitHub는 Git으로 관리하는 파일을 인터넷에 저장하고 공유할 수 있는 온라인 서비스입니다.

GitHub에서는 다음과 같은 작업을 할 수 있습니다.

- 파일 저장
- 변경 이력 관리
- 팀원과 공동 작업
- 프로그램 코드 공유
- 프로젝트 진행 상황 관리
- 웹페이지 제작
- 교육자료 및 연구자료 관리

---

### 3.3 Git과 GitHub의 차이

| 구분 | Git | GitHub |
|---|---|---|
| 의미 | 파일 변경 이력 관리 프로그램 | Git 저장소를 제공하는 온라인 서비스 |
| 사용 위치 | 개인 컴퓨터 | 인터넷 |
| 주요 기능 | 버전 관리 | 저장, 공유, 협업 |
| 인터넷 필요 여부 | 필수 아님 | 필요함 |

> Git은 파일 변경을 기록하는 도구이고, GitHub는 그 기록을 인터넷에서 관리하는 공간입니다.

## 5. GitHub 주요 용어

### 5.1 저장소

저장소는 프로젝트 파일을 보관하는 공간입니다.

영어로는 `Repository`라고 하며, 줄여서 `Repo`라고도 부릅니다.

하나의 저장소에는 다음과 같은 자료를 넣을 수 있습니다.

- 문서
- 이미지
- 프로그램 코드
- 엑셀 자료
- 설명 파일
- 데이터 분석 파일

---

### 5.2 커밋

커밋은 파일의 변경 내용을 하나의 기록으로 저장하는 작업입니다.

커밋할 때는 무엇을 변경했는지 설명하는 메시지를 작성합니다.

예시:

```text
강의계획서 초안 작성
1주차 학습목표 추가
오탈자 수정
````

좋은 커밋 메시지는 변경 내용을 짧고 분명하게 작성합니다.

---

### 5.3 브랜치

브랜치는 원본 파일에 직접 영향을 주지 않고 별도로 작업할 수 있는 공간입니다.

예를 들어 다음과 같이 사용할 수 있습니다.

```text
main           : 최종 자료
lecture-update : 강의자료 수정본
test           : 실험용 자료
```

첫 시간에는 개념만 이해하고, 실제 브랜치 실습은 다음 교육에서 진행합니다.

---

### 5.4 README 파일

README 파일은 저장소를 소개하는 설명서입니다.

일반적으로 다음 내용을 작성합니다.

* 프로젝트 이름
* 프로젝트 목적
* 사용 방법
* 작성자
* 주요 기능
* 파일 구성

README 파일은 보통 `README.md`라는 이름으로 작성합니다.

---

### 5.5 마크다운

마크다운은 간단한 기호를 사용하여 문서를 작성하는 방식입니다.

파일 확장자는 `.md`를 사용합니다.

예시:

```markdown
# 제목

## 소제목

- 항목 1
- 항목 2

**중요한 내용**

[링크 이름](https://example.com)
```

## 6. GitHub 계정 만들기

### 실습 1: 회원가입

1. 웹 브라우저에서 GitHub에 접속한다.
2. 회원가입 메뉴를 선택한다.
3. 이메일 주소를 입력한다.
4. 비밀번호를 설정한다.
5. 사용자 이름을 입력한다.
6. 이메일 인증을 완료한다.
7. GitHub에 로그인한다.

### 사용자 이름 작성 시 주의사항

* 영문과 숫자 중심으로 작성한다.
* 너무 긴 이름은 피한다.
* 공식 활동에 사용할 경우 전문적인 이름을 사용한다.
* 개인정보가 지나치게 노출되지 않도록 주의한다.

사용자 이름 예시:

```text
smart-professor
tax-accounting-lab
my-data-project
```

## 8. 저장소 만들기

### 실습 2: 새로운 저장소 생성

화면 오른쪽 위의 `+` 버튼을 누른 후 `New repository`를 선택합니다.

다음 항목을 입력합니다.

### Repository name

저장소 이름을 입력합니다.

예시:

```text
github-first-class
accounting-study
tax-learning-materials
```

저장소 이름은 다음 기준으로 작성하는 것이 좋습니다.

* 영문 소문자 사용
* 띄어쓰기 대신 하이픈 사용
* 프로젝트 내용을 알 수 있도록 작성
* 너무 긴 이름은 피하기

---

### Description

저장소의 목적을 간단히 작성합니다.

예시:

```text
GitHub 기초 교육을 위한 첫 번째 실습 저장소
```

---

### 공개 범위 설정

#### Public

누구나 저장소를 볼 수 있습니다.

다음 자료에 적합합니다.

* 공개 강의자료
* 공개 프로그램
* 개인 포트폴리오
* 공개 연구자료

#### Private

허가받은 사용자만 저장소를 볼 수 있습니다.

다음 자료에 적합합니다.

* 내부 업무자료
* 개인정보 포함 자료
* 학생 성적 자료
* 기업 재무자료
* 공개 전 연구자료

> 개인정보, 기업 비밀, 학생 성적, 주민등록번호, 계좌번호 등은 공개 저장소에 올리면 안 됩니다.

---

README 파일을 함께 만들면 저장소 설명을 바로 작성할 수 있습니다.

### 저장소 생성 완료

모든 항목을 입력한 후 다음 버튼을 선택합니다.

```text
Create repository
```

## 9. README 파일 수정하기

```markdown
서일대학교 세무회계학과

2026년 7월
```

## 10. 커밋하기

파일을 수정한 후에는 변경 내용을 저장해야 합니다.

GitHub에서는 이를 커밋이라고 합니다.

### 커밋 메시지 작성 방법

좋은 예시:

```text
README 파일 작성
프로젝트 설명 추가
학습 목표 수정
작성자 정보 추가
```

좋지 않은 예시:

```text
수정
변경
작업
123
```

커밋 메시지는 변경 내용을 알아볼 수 있도록 작성해야 합니다.

## 13. 파일 수정 이력 확인하기

GitHub에서는 파일이 어떻게 변경되었는지 확인할 수 있습니다.

### 확인 방법

1. 파일을 선택한다.
2. `History`를 선택한다.
3. 커밋 목록을 확인한다.
4. 원하는 커밋을 선택한다.
5. 변경 전후 내용을 비교한다.

변경 이력에서는 일반적으로 다음 내용을 확인할 수 있습니다.

* 작성자
* 작성 시각
* 커밋 메시지
* 추가된 내용
* 삭제된 내용

## 14. 공개 저장소 사용 시 보안 수칙

GitHub 사용 시 가장 중요한 것은 정보 보호입니다.

### 공개하면 안 되는 정보

* 개인 비밀번호
* API 키
* 인증서
* 주민등록번호
* 여권번호
* 계좌번호
* 신용카드 정보
* 학생 성적
* 기업 영업비밀
* 공개 전 연구자료

### 잘못 업로드했을 때

파일을 삭제하더라도 과거 커밋에 정보가 남을 수 있습니다.

따라서 중요한 정보가 노출되었다면 다음 조치가 필요합니다.

1. 해당 파일을 즉시 삭제한다.
2. 비밀번호나 API 키를 변경한다.
3. 저장소를 비공개로 전환한다.
4. 필요하면 저장소 변경 이력을 정리한다.
5. 관련 관리자에게 보고한다.

## 18. 1회차 핵심 정리

* Git은 파일의 변경 이력을 관리하는 도구입니다.
* GitHub는 파일과 변경 이력을 인터넷에서 저장하고 공유하는 서비스입니다.
* 저장소는 프로젝트 파일을 보관하는 공간입니다.
* 커밋은 파일의 변경 내용을 기록하는 작업입니다.
* README 파일은 저장소를 설명하는 문서입니다.
* 마크다운은 간단한 기호로 문서를 작성하는 방식입니다.
* 공개 저장소에는 개인정보와 보안정보를 올리면 안 됩니다.
